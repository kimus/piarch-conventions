This is a FULL TECHNICAL SPECIFICATION review (G1), NOT an idea review; a proposal is the specification's draft form and is reviewed the same way. Examine the design and architecture, feasibility, dependencies and environment, data/control flow, compatibility with living specs, security and trust boundaries, failure/recovery behavior, and verification strategy. Treat unresolved technical decisions that prevent safe implementation as blocking, and treat any question still listed under `## Open Questions` as blocking: the gate passes only on an honest `- none`. Distinguish explicit non-goals from missing required design. Detailed normative requirements belong in a capability delta, and acceptance criteria in a deliverable contract; do not demand either in the specification. Judge for design completeness, not for per-requirement scenarios. Do not infer implementation or tests absent from the snapshot. Ready means suitable for human baseline approval, not verified implementation.
